# Stitch

A small, native, Skitch-like screenshot annotation app. One codebase, macOS and
iOS/iPadOS.

It does three things and nothing else:

1. Takes **one** image — from the **clipboard by default**, or from a file.
2. Lets you **annotate** it.
3. Lets you **copy the finished image back to the clipboard** or **save it as a PNG**.

Out of scope by design: screen capture, video, cloud/sharing, multiple documents,
non-PNG output.

## Requirements

| | |
|---|---|
| macOS | 26.0 or later |
| iOS / iPadOS | 26.0 or later |
| Xcode | 26 or later |
| [XcodeGen](https://github.com/yonaskolb/XcodeGen) | `brew install xcodegen` |

`Stitch.xcodeproj` and `Stitch/Resources/Info.plist` are **generated** from
[project.yml](project.yml) and are not committed. Regenerate them after changing the
project layout or build settings.

## Run it

```sh
brew install xcodegen
make run
```

`make run` generates the project, builds the macOS app, and launches it. If nothing is
on the clipboard the app opens on an empty state offering **Paste** and **Open…**.
Otherwise it loads the clipboard image immediately.

The `Makefile` points `DEVELOPER_DIR` at `/Applications/Xcode.app` when the command
line tools are the selected toolchain, so `make` works without `sudo xcode-select -s`.
To build in Xcode instead:

```sh
xcodegen generate && open Stitch.xcodeproj
```

Then pick the **Stitch** scheme and either the *My Mac* or an iOS Simulator destination.

### Tests

```sh
make test          # StitchKit unit tests (Swift Testing)
```

145 tests cover the annotation geometry, the dirty-rect undo/redo patches, crop, rotate
and straighten maths, blend modes, PNG export and the clipboard-to-PNG pipeline.

### Signing

The project uses manual ad-hoc signing (`CODE_SIGN_IDENTITY = "-"`) so local builds
work with no developer team. To run on a physical iOS device, set your team and switch
to automatic signing for the `Stitch` target.

## The app

The toolbar mirrors classic Skitch, top to bottom:

| Tool | Options behind the corner chevron |
|---|---|
| Arrow | thickness, head length and width |
| Text | font, size, bold/italic/underline, colour, alignment, text background |
| Rectangle | **rectangle · rounded rectangle · oval · line**, corner radius, fill, thickness |
| Marker | marker / highlighter / eraser, thickness |
| Stamp | the ✕ ! ? ✓ ♥ badge set, quick emoji, the system emoji picker |
| Crop | rotate 90° left/right, flip H/V, **straighten**, aspect presets, transparency mode, Apply/Cancel |
| — divider — | |
| Foreground colour | palette |
| Background colour | palette, including "no fill" |

**The arrow is drawn head-first**, as in Skitch: press on the thing you are pointing at and
drag the tail out behind it, so the head lands exactly where you clicked. Hold **shift**
while dragging to make shapes square and to snap arrows and lines to 45°.

Every tool flyout has a **pin** in its header. Pinning docks the options beside the tool
strip so they stay reachable while you draw, instead of closing as soon as you click back
to the canvas.

Keyboard: `⌘V` paste · `⌘C` copy image · `⌘O` open · `⌘S` save PNG · `⌘Z` / `⇧⌘Z`
undo/redo · `⌘+` / `⌘-` / `⌘0` / `⌘9` zoom.

Copy and Save write a PNG that honours the transparency mode under the crop menu: keep the
alpha channel, or flatten onto white or black.

## Design decisions

| # | Decision | Choice |
|---|---|---|
| 1 | Project structure | Multiplatform SwiftUI app over a local `StitchKit` Swift Package, project generated by XcodeGen |
| 2 | Annotation lifecycle | **Skitch-style**: strokes bake into the bitmap, the active tool stays active until you switch, undo/redo works on the flattened result |
| 3 | "Alpha channel" | An export toggle — keep alpha, or composite onto white/black |
| 4 | Minimum OS | macOS 26 / iOS 26 |
| 5 | Output format | PNG only |
| 6 | Entry point | One window; the clipboard image loads automatically on launch |
| 7 | Rotation | 90° steps, H/V flip and a free straighten slider, staged non-destructively until the crop is applied |
| 8 | Stamps | The ✕ / ! / ? / ✓ / ♥ badge set plus the system emoji picker |
| 9 | Text | Family, size, bold/italic/underline, colour, alignment, optional background |
| 10 | Arrow | Drawn head-first: the head lands where you press, the tail follows the drag |
| 11 | Tool flyouts | Pinnable, so a tool's options can stay docked open while you draw |

### Why a raster core

Because annotations bake in (decision 2), `StitchKit` is a compositor rather than a
scene graph:

- **`CanvasBitmap`** owns one mutable `CGBitmapContext`, presented with a top-left
  origin so annotation geometry is plain image-pixel coordinates.
- **Preview and commit share one draw path** (`Renderer.draw`). The in-flight gesture is
  rendered over a copy of the pixels it covers, which is what makes the highlighter's
  multiply blend and the eraser's clear blend preview exactly what gets committed.
- **History stores dirty-rect pixel patches** — the `before` and `after` bytes of just
  the affected bounding box — so an undo step on a 5K screenshot costs kilobytes
  instead of another full-size bitmap. Crop, rotate and flip replace the surface
  wholesale and store a single canvas-to-canvas entry.
- **Crop is the one staged island.** Rotate, flip and straighten rebuild a preview image
  from the untouched original; the crop rect is dragged over that; Apply bakes everything
  as one undoable step. Cancel restores the original exactly.
- Rendering uses only CoreGraphics and CoreText, so `StitchKit` never imports AppKit or
  UIKit. The only platform-specific code is the pasteboard and file-panel adapters in
  the app target.

## Layout

```
project.yml                  XcodeGen spec: one target, macOS + iOS destinations
StitchKit/                   platform-agnostic core (Swift Package)
  Sources/StitchKit/
    Model/                   annotations, styles, tools, crop transform, stamps
    Canvas/                  CanvasBitmap — the mutable pixel surface
    Render/                  Renderer, CoreText text and stamp rasterisers
    History/                 dirty-rect patches and the undo/redo stacks
    Tools/                   drag-to-annotation sessions, crop session
    Editing/                 ImageDocument (pixels + history), EditorModel (app state)
    Export/                  rotate/flip/crop ops, alpha modes, PNG encode/decode
  Tests/StitchKitTests/      145 tests
Stitch/                      SwiftUI app
  Views/                     toolbar, canvas, crop overlay, format bars, action bar
  Platform/                  NSPasteboard/UIPasteboard adapters, PNG file document
  Commands/                  macOS menu bar
.github/workflows/ci.yml     runs the tests and both builds on macos-26
```

## CI

`CI` runs on every pull request and push to `main`:

- **StitchKit tests** — `swift test` (unit tests).
- **Build app** — a clean `xcodegen generate`, then a Debug build for macOS *and* for
  the iOS Simulator.
